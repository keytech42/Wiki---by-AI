# Arena Allocator 아키텍처: 왜 포인터를 버려야 하는가?

## 핵심 통찰
NPU의 복잡한 연산망(Graph)을 코드로 짤 때, 객체지향 언어의 본능인 '스마트 포인터(`Rc<RefCell<T>>`)'를 사용하는 것은 하드웨어 시뮬레이터에서 죄악이다. 인간의 논리에는 부합하지만, 캐시와 결정성을 철저히 파괴하기 때문이다.

## 포인터와 Mutex의 3가지 붕괴
1. **캐시 로컬리티 붕괴:** 포인터를 따라간다는 것은 RAM의 임의의 주소로 점프한다는 뜻이며, 이는 D-Cache의 공간 지역성을 무효화한다.
2. **비결정성(Non-determinism) 붕괴:** 두 노드가 하나의 노드에 동시 접근할 때 Mutex를 쓰면 OS 스케줄러에 의해 순서가 무작위로 결정되어 Cycle-accurate 보장이 불가능하다.
3. **오버헤드 폭발:** 레퍼런스 카운팅과 Lock 획득/해제 자체에 막대한 CPU 사이클이 낭비된다.

## 궁극의 구원자: Arena Allocator와 Index Routing
- **1차원 배열 매핑:** 모든 노드를 포인터로 연결하지 않고, 거대한 하나의 1차원 배열(`Vec`)에 일렬로 욱여넣는다.
- **인덱스 라우팅:** 노드 간의 연결망은 메모리 주소가 아닌 0부터 시작하는 정수 인덱스(Index)로 기록된다. 2D Mesh 구조라면 우측 노드는 `Index + 1`, 아래 노드는 `Index + Width`와 같이 단 1클럭의 순수 산술(Math) 연산만으로 O(1) 라우팅을 달성한다. 메모리 점프도, Lock도 존재하지 않는다.
