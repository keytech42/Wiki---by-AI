# Rust Enum (Tagged Union)의 메모리 레이아웃 원리

## 핵심 통찰
C언어의 Enum이 단순한 정수형 상수라면, Rust의 Enum은 상태(Tag)와 추가 데이터(Payload)를 물리적으로 강제 결합하는 **대수적 데이터 타입(Algebraic Data Type)**이자 **Tagged Union**이다.

## 컴파일러의 지독한 최적화 로직 (사용자 리버스 엔지니어링)
1. **Tag의 가변성:** Enum은 현재 어떤 상태인지를 기억하기 위한 최소한의 공간(Tag)을 가진다. 상태의 수가 256개 이하라면 컴파일러는 `u8`(1 Byte)을 사용하지만, 이를 초과하면 자동으로 `u16`(2 Bytes) 등으로 펌핑하여 메모리 낭비를 극한으로 막는다.
2. **Payload와 정렬(Alignment) 규칙:** Enum이 품을 수 있는 다양한 상태 중 **'가장 큰 Payload'**를 기준으로 전체 메모리 구획이 정해진다. 또한 구조체와 완벽히 동일한 N배수 패딩(Padding) 룰이 적용된다.
3. **크기 고정의 마법:** 어떠한 상태를 가지든 간에 Enum의 전체 크기는 `Tag + 최대 Payload + Padding`으로 컴파일 타임에 **영구 고정**된다.

## 시뮬레이터 아키텍처 관점
파이썬처럼 상태에 따라 크기가 다른 객체를 힙(Heap)에 뗐다 붙였다 하는 짓은 캐시 미스의 주범이다. Rust의 Enum은 크기가 고정되어 있으므로 거대한 1차원 배열(`Vec`)에 일렬로 욱여넣을 수 있으며, 상태가 변해도 그 고정된 바이트 안에서 비트 값만 덮어쓰므로 성능이 압도적이다.
